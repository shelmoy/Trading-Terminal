## New functionality

1. Custom chart intervals, collapsible timeframe groups, and shared favourites. Each chart pane retains its own selected interval.
2. Compatible intervals can be derived from available history, including 7-minute bars from minute data and calendar periods from daily data. Finer history cannot be invented from coarser candles.
3. Indicators can request independent daily history and confirmed observations, such as a daily EMA 200 on an intraday chart.
4. Historify gains corresponding timeframe support and improved toolbar containment.
5. Strike Profile at `/strikeprofile`, also available from Tools, adds GEX/DEX heatmaps by strike and expiry, estimated gamma-flip levels, and call/put walls. These are model-based estimates using the broker's available option-chain data, not measured dealer positions or guaranteed trading signals.
6. Flattrade empty order, trade, and position books now produce debug-level messages.
7. Upstream deployment/setup documentation was updated.

## Custom features preserved

- Scalper layout, styling, quantities, CE/PE selection independence, and ATM defaults.
- Custom Renko V2/V3/V4 chart types and their distinct vector icons.
- Gaussian Filter Trend styling and simplified display; Alpha Trend V2 changes.
- FYERS selection and OAuth support.
- Broker-aware P&L and required-margin integration.
- Native SDK candle defaults and custom order-button colours.
- Seconds history captured from actual observed ticks, exchange-session guards, and fast chart previews.

The timeframe integration was reconciled with the local seconds-history and cache layers instead of replacing them. Supported interval checks now use the official timeframe planner. Renko V4 retains its price-driven interval guard.

## Recurring maintenance authorization

The daily task runs at **09:00 Asia/Calcutta** and now checks, merges, builds, activates, and pushes safe updates automatically. It creates recovery points, preserves custom work, excludes secrets and runtime data, and never force-pushes or executes trading actions. Destructive migrations, unsafe conflicts, failed builds, failed activation, or authentication errors must be reported rather than bypassed.

Successful runs report versions, changes, recovery/migration status, build and HTTP results, restart status, commit SHA, and GitHub push status. The task stays quiet when nothing new needs action.
